# 轻量后端与完整界面

`CheckinService` 提供完整、独立于界面的业务服务；`LiteBrowserRunner` 通过系统 Edge/Chrome 的 DevTools Protocol 执行网页流程。这些模块不导入 Tk、Qt、WebView、Playwright 或 Node。

## 模块划分

| 模块 | 职责 |
| --- | --- |
| `service.py` | 保存配置、任务互斥、取消、每日调度、校园网独立调度、完成记录、重试、退出与防休眠 |
| `schedule_policy.py` | 从旧 App 原样抽出的排期策略，旧界面与新服务共用 |
| `browser_flow.py` | 从旧浏览器模块抽出的登录、菜单、班次、定位、提交与复核规则，新旧驱动共用 |
| `browser.py` | 旧 Playwright 运行入口，继续承载旧界面 |
| `cdp_transport.py` | 独立 Edge/Chrome 临时进程、自动回退、取消和有界超时、临时目录清理 |
| `cdp_browser.py` | 浏览器页面与元素操作、响应事件、设备/时区/定位设置、Cookie/localStorage 恢复与保存 |
| `lite_browser.py` | 把轻量驱动连接到共享网页流程，公开接口与旧 Runner 一致 |
| `core.py`、`storage.py`、`campus_network.py` | 继续使用现有规则、DPAPI 与校园网认证实现 |
| `offline_school.py`、`backend_selftest.py` | 仅用于本地合成页面的端到端验证，所有请求被本地完成或中止 |
| `lite_cli.py` | 无界面的自检入口，以及显式指定数据目录的单次业务入口 |

## 完整界面的接口

由界面创建 `Store` 并注入 `CheckinService`，定时调用 `tick()`，通过 `snapshot()` 读取状态。快照包含账户名、设置、任务状态、下次执行时间、有限日志和操作结果，不包含密码、Cookie 或 localStorage。

- `save_account(username, password='')`：同一账户可沿用密码；更换账户必须填写密码，并清除旧会话和内存中的完成/排期缓存。
- `save_schedule(start, end, retry_minutes)`：使用现有时段校验，保留已生成随机延迟，调整时间后重新计算执行时间。
- `save_location(mode, latitude, longitude)`：手动位置使用原有格式校验与 DPAPI；保存时不在日志显示坐标。
- `save_network(enabled, username, password, carrier)`：独立保存校园网凭据；关闭时不要求损坏的旧凭据可读。
- `start_schedule()` / `stop_schedule()`：持久化启动或暂停；校园网检测继续受自身开关控制。
- `launch('check'|'manual'|'network')`：启动单次任务；`check` 不提交、不写完成记录、不生成完成后的随机排期。
- `stop_current()`：停止当前任务，保留定时开关；取消后按既有重试策略计算下次执行。
- `editing_settings()`：上下文存在期间暂停新自动任务；查看日志不应进入该上下文。
- `set_login_start(enabled, consent=...)`：调用界面注入的、指向正确轻量版入口的自启动注册器；注册失败时回滚设置。只有用户在正式界面明确启用后才写入启动项，预览及自检使用模拟注册器。
- `request_exit()` / `shutdown(timeout)`：协作取消，等待结果回收后释放实例锁、日志与防休眠线程；退出保留上次定时开关用于下次恢复。

同一服务最多一个任务；工作线程已经返回但结果尚未由 `tick()` 回收时，也不允许第二个任务或修改账户。跨午夜结果按浏览器实际核验的日期归属。

## 浏览器驱动行为

默认先启动 Edge，失败后尝试 Chrome。使用随机本地调试端口和专属临时配置目录，不连接默认用户配置，不按浏览器进程名关闭其他窗口。取消会打断协议等待和等待人工验证，退出后清理本次实例。

兼容旧 `session.dat` 中的 Playwright storage-state 格式。恢复受限于学校域名的 Cookie 和两个认证/业务 origin 的 localStorage；localStorage 在进入业务页面前只初始化一次，避免覆盖登录后更新的 token。保存保留旧引擎所需的 Cookie 字段，并继续使用现有 DPAPI。

网页业务继续通过正常表单和页面组件：支持隐藏重复表单、密码框聚焦解锁、一次自动登录、验证码/二次认证等待人工处理、实时菜单入口、班次接口、已完成/免打卡跳过、时段与范围判断、手动位置或电脑定位，以及新页面独立复核。敏感填写会再次核对登录 URL；复核开始后移除旧页面的响应监听，避免旧页面影响新查询。

没有添加验证码识别，也没有把网页流程换成直接伪造打卡请求。手动定位保留原有配置语义，学校页面继续负责位置转换、地址解析和范围判断。

## 运行和验证

```powershell
# 完全离线合成页面：Edge 与 Chrome，真实启动浏览器，但没有学校请求出网。
../work/lite-venv/Scripts/python.exe source/lite_cli.py --self-test --report work/backend-check.json

# 新控制器及 CDP 专项测试
../work/lite-venv/Scripts/python.exe -m unittest discover -s source/tests -p test_service.py -v
../work/lite-venv/Scripts/python.exe -m unittest discover -s source/tests -p test_cdp_browser.py -v
```

显式真实环境单次检查入口：`python source/lite_cli.py --data-dir <已有数据目录> --mode check --accept-disclaimer`。它会实际连接学校并使用指定目录的账户和位置配置。本次完整界面迁移使用现有加密配置的隔离副本完成了 Edge、Chrome 的真实仅检查：登录、班次查询、浏览器读取手动定位配置通过；学校当时尚未开放，页面范围判断需在开放时段再验。没有提交真实打卡，也没有改动原数据目录。

完整轻量版从 `source/lite_app.py` 启动，`lite_bridge.py` 连接账户、排期、定位、校园网、自启动、导入和记录等界面；`lite_native.py` 处理原生圆角、缩放和托盘。旧版仍可从 `source/app.py` 启动。离线自检中的提交与复核仅面向本地合成网页，真实业务提交及电脑设备定位尚未验证。
